# 0049 — UI upgrade: reward chance visibility + design fixes (approved 2026-11-21)

Branch `feature/0049-ui-upgrade` in a separate git worktree. No code before owner approval. Steps go to `tasks/todo.md` (updated in every step; not counted in a step's file list). Web UI is English-only; the Telegram bot is not touched.

Every step touches at most 3 files, tests included.

Verification after every step: `cd frontend && npx vitest run`, `cd frontend && npm run build`, `uv run pytest tests/ -m "not local_only"`, `uv run ruff check src/`, then a look in the browser at 375px and 1280px in night_arcade, ticket_stub, quest_log and clean_modern.

Baseline: on main, vitest has 3 failing tests, all in `frontend/tests/Layout.spec.js`. Step 1 fixes them, so every later step must be fully green.

## Facts the plan rests on

- Reward chance: `p(s) = min(20 + 30*(1 - e^(-(s-1)/5.5)), 50)`, constants in `settings.py` (`REWARD_CHANCE_*`), computed by `reward_service.calculate_reward_chance`. Displayed rounded: p(1)=20, p(7)=40, p(21)=49, p(24)=50.
- Dashboard habit props today: `streak`, `completedToday`, `rewardChance` (unfinished: `round(p(state.next_streak))`; completed: `round(100 - log.total_weight_applied)`), `todayResult`, `freezeCount`, `freezeUsedFor`, `freezeAtRisk`.
- `night_arcade`, `ticket_stub`, `quest_log` set `habitCard.showOdds: false`. This plan reverses that decision (recorded in `docs/features/0048_PLAN.md` and `scratch/design_review/implementation/README.md`) on the owner's request.
- A colour token must be declared in three places: `app.css` `@theme`, each `[data-theme]` block in `app.css`, and each theme's `cssVars` in `themes/index.js`.
- `reward_service.get_user_reward_progress` deliberately orders zero-piece, pending, ACHIEVED last; pinned by `tests/test_reward_filtering.py`; shared with the bot. Not changed here.
- Whole-card `opacity-60` on completed cards is overridden by the entrance animation (`fadeIn ... both`) in themes with a card entrance; computed opacity is 1 in night_arcade.
- Inertia's `router.post` returns `void`. `onStart` fires when the request starts and `onFinish` always fires when it ends (success, HTTP error or network exception). `onError` fires only for validation errors in `props.errors`, which `logout_view` never returns, so it cannot be used to detect a failed logout.
- No theme currently uses the `swipe-reveal` interaction.

## Step 8 — `OddsChip` component

Files: new `frontend/src/components/OddsChip.vue`, new `frontend/tests/OddsChip.spec.js`.

- Props: `rewardChance` (number), `completed` (bool), `nextStreak` (number, default 1), `chance` (`{curve, cap}` or null), `oddsStyle`, `badgeClass` (string, default ""; the parent passes `tc.badge.base`). The component does not call `useTheme()` itself, so existing spec mocks keep working.
- Label — unfinished: `🎲 40% next` (badge, chip), `ODDS 40%` (stub), `drop: 40%` (drop). Completed: `rolled at 29%` in every style.
- Look via a static class map keyed by `oddsStyle`: `badge` uses the `badgeClass` prop; `chip` accent outline; `stub` mono with an explicit scoped `font-family: 'IBM Plex Mono', ui-monospace, monospace` (no reliance on `font-mono`); `drop` plain mono text.
- The chip is a `<button>` with `aria-expanded` / `aria-controls`; activating it toggles a hint (no modal, no teleport). The id for `aria-controls` comes from Vue's `useId()` (Vue 3.5 is installed). Layout: the component's root is a wrapper with the static class `contents`, holding the chip and the hint; the hint has `basis-full w-full`. The parent's meta row gets `flex-wrap` (added in step 9), so the hint wraps onto its own full-width line under the streak, odds and freeze items and never sits beside them. Min tap height 32px; hint text ≥ 12px.
- Hint, unfinished: "Next completion 40%, the one after 42%. Levels off near 50%. If the streak breaks, it starts again at 20%." Completed: "Today's roll was at 29%. Next completion 42%." Values come from `chance.curve` with the clamp from step 6; "near 50%" uses `chance.cap`.
- Hint also shows a small inline SVG polyline of `chance.curve` with a dot at `nextStreak` (clamped), `aria-hidden`.
- Without `chance` (null): the chip still shows `rewardChance`; the hint shows one fixed sentence in both states — "Your chance grows with your streak and starts over if the streak breaks." — and no curve.
- The chip stops propagation of `pointerdown`, `touchstart`, `touchmove` and `touchend` so a future swipe wrapper is not triggered.
- Spec: label per style and state, toggle + `aria-expanded`, clamp at streak 40, null `chance`.
