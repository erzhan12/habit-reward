# Feature 0047: Add Habit Reminder Notification at 13:00

## Description

Add a new habit reminder notification at **13:00** local time, in addition to the existing ones at **21:00**, **22:00**, and **23:00** (GitHub issue [#69](https://github.com/erzhan12/habit-reward/issues/69)).

Reminders notify users about pending (not-yet-completed-today) habits. Scheduling must be **timezone-aware**, using each user's stored IANA timezone (`User.timezone`, default `UTC`) — consistent with feature 0033.

**Research finding:** The repository does not currently contain habit reminder scheduling code. `TODO.md` lists "Habit Reminders" as unimplemented (`src/bot/handlers/reminder_handler.py`). Issue #69 describes production behavior at 21/22/23. During implementation, first search for any existing `HABIT_REMINDER_HOURS` (or equivalent) constant — if absent, introduce the reminder scheduler with hours **`[13, 21, 22, 23]`** so 13:00 is added alongside the three evening slots the issue references.

## Files to Create

### `src/bot/reminder_scheduler.py`

Central scheduling and send logic (keeps handler wiring thin).

- **`HABIT_REMINDER_HOURS: tuple[int, ...] = (13, 21, 22, 23)`** — single source of truth for reminder times. This is the change for issue #69: add `13` to the existing `(21, 22, 23)` set.
- **`_sent_reminders: dict[tuple[int, date, int], bool]`** — in-memory dedup cache keyed by `(user_id, local_date, local_hour)`. Prevents double-send if the repeating job fires more than once within the same hour. Safe for single-process deployment (same constraint as WebSocket `ConnectionManager`). After each tick, prune entries whose `local_date` is before today in UTC (drop stale keys; retention policy: keep only current and future local dates). Document this alongside the single-process deployment note.
- **`async def check_and_send_reminders(context: ContextTypes.DEFAULT_TYPE) -> None`**
  - Query active users with a `telegram_id` (new repo method below).
  - For each user, wrap the **entire per-user loop body** (steps 2–9 below) in try/except; log `user.id` and the exception, then continue to the next user (one bad user must not abort the tick or block others):
    1. Resolve `user_tz = user.timezone or 'UTC'`.
    2. Compute `now_local = get_user_local_now(user_tz)` (UTC fallback on invalid IANA names; see `src.bot.timezone_utils`).
    3. Skip unless `now_local.minute == 0` (fire on the hour only).
    4. Skip unless `now_local.hour in HABIT_REMINDER_HOURS`.
    5. Skip if dedup key `(user.id, now_local.date(), now_local.hour)` already sent.
    6. `pending = await maybe_await(habit_service.get_active_habits_pending_for_today(user.id, target_date=get_user_today(user_tz)))` (same resolved timezone as step 2; import `maybe_await` from `src.utils.async_compat`).
    7. Skip if no pending habits.
    8. Send proactive Telegram message: `await context.bot.send_message(chat_id=user.telegram_id, text=msg('REMINDER_PENDING_HABITS', user.language), reply_markup=build_simple_habit_selection_keyboard(pending, user.language))`.
    9. Record dedup key.
  - After processing all users, prune `_sent_reminders` entries whose `local_date` is before today in UTC.
- **`def register_reminder_jobs(application: Application) -> None`**
  - Guard: if `application.job_queue` is `None`, log warning and return (same pattern as `settings_handler.py` API-key auto-delete).
  - Register `application.job_queue.run_repeating(check_and_send_reminders, interval=60, first=30, name="habit_reminder_tick")`.
  - Log registered hours from `HABIT_REMINDER_HOURS`.

## Algorithm: Timezone-Aware Reminder Tick

1. **Startup:** Bot application registers a repeating job every 60 seconds (`register_reminder_jobs`).
2. **Each tick:** `check_and_send_reminders` runs.
3. **User iteration:** Load all `is_active=True` users with `telegram_id`.
4. **Local time check:** For user timezone `tz`, compute `now_local = get_user_local_now(tz)` (UTC fallback on bad IANA names). Only proceed when `minute == 0` and `hour ∈ {13, 21, 22, 23}`.
5. **Dedup:** Skip if reminder already sent for this `(user, local_date, hour)`.
6. **Pending habits:** `pending = await maybe_await(habit_service.get_active_habits_pending_for_today(user.id, target_date=get_user_today(tz)))`.
7. **Send:** If pending habits exist, `await context.bot.send_message(chat_id=user.telegram_id, text=msg('REMINDER_PENDING_HABITS', user.language), reply_markup=build_simple_habit_selection_keyboard(pending, user.language))`. Mark dedup.
8. **No-op cases (no message):** all habits completed, no active habits, inactive user, outside reminder hours, duplicate within same hour.

This approach keeps 21/22/23 behavior unchanged (same hour set, just extended with 13) and satisfies timezone-aware local-time firing without per-user `run_daily` jobs that would need rescheduling on timezone changes.

## Unit Tests

**File:** `tests/bot/test_reminder_scheduler.py`

| Scenario | Description |
|----------|-------------|
| `HABIT_REMINDER_HOURS` includes 13 and preserves 21/22/23 | Assert tuple is `(13, 21, 22, 23)` |
| Sends at 13:00 local | Mock user `timezone='Asia/Almaty'`, freeze `now_local` to 13:00, pending habits exist → `bot.send_message` called once |
| Sends at 21/22/23 unchanged | Same test pattern for hours 21, 22, 23 — verify still fires (regression guard) |
| Skips outside reminder hours | `now_local.hour=14` → no send |
| Skips non-zero minute | `hour=13, minute=30` → no send |
| Skips when all habits completed | `get_active_habits_pending_for_today` returns `[]` → no send |
| Skips inactive users | User with `is_active=False` not in query results |
| Dedup within same hour | Two ticks both within the same hour with `minute == 0` (e.g. 13:00:10 and 13:00:50) → `send_message` called only once |
| Timezone fallback | User with `timezone=None` or invalid IANA name uses UTC for local hour check (via `get_user_local_now`) |
| Send failure isolated | Exception anywhere in per-user loop body (e.g. `send_message` raises) for one user → other users still processed |
| `register_reminder_jobs` no-op without JobQueue | `application.job_queue = None` → no crash, warning logged |
| `register_reminder_jobs` registers repeating job | Verify `run_repeating` called with `interval=60` |

Use `unittest.mock.patch` on `src.bot.timezone_utils.get_user_local_now` (and `get_user_today` where needed; same pattern as `tests/bot/test_timezone_utils.py`) and mock `habit_service`, `user_repository`, and `context.bot.send_message`.
